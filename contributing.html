Download

下载单个文件

不需要安装 Git，直接在浏览器中下载仓库里的任意文件。

  GitHub 网页操作
  1. 打开仓库页面 github.com/shiren23/citrus-yield-prediction
  2. 点击进入目标文件所在的文件夹，再点击文件名
  3. 在文件内容页面上方，点击右侧的 Raw 按钮
  4. 右键 → 另存为（Save As），保存到本地 对于图片等二进制文件，直接右键 Raw 链接即可保存。也可以点击 Raw 后，浏览器会直接下载。
  5. 下载整个文件夹：在文件夹页面点击绿色 Code 按钮 → Download ZIP GitHub 不支持单独下载某个文件夹，只能下载整个仓库的 ZIP 然后提取需要的部分。
💡
快捷方式：在任意文件页面，直接按 Raw 按钮旁边的 Download 图标（⬇），一步完成下载。
Upload

上传单个文件

直接在 GitHub 网页上上传文件，无需命令行。

  GitHub 网页上传
  1. 打开仓库页面，进入你想要上传到的文件夹（如 docs/）
  2. 点击页面右上角的 Add file 按钮
  3. 选择 Upload files
  4. 将文件拖拽到虚线框中，或点击 choose your files 选择文件 支持一次上传多个文件。也可以上传整个文件夹（需使用 Chrome/Edge 浏览器）。
  5. 在下方填写 Commit 信息：简要描述上传了什么
    例如：docs: 添加训练记录 #001
  6. 选择 Commit directly to the main branch（直接提交到 main），然后点击绿色 Commit changes 按钮
⚠️
上传限制：单个文件不能超过 25MB（通过网页上传）。
超过 25MB 的文件（如模型权重），请使用命令行上传，或通过网盘分享链接。
Edit Online

在线编辑文件

在 GitHub 网页上直接修改已有文件的内容。

  GitHub 网页编辑
  1. 打开仓库，点击进入要编辑的文件
  2. 点击文件内容右上角的 铅笔图标 ✏️（Edit this file）
  3. 在编辑器中修改内容 编辑器支持 Markdown 预览：点击上方 Preview 标签查看渲染效果。
  4. 修改完成后，在下方填写 Commit 信息，描述你改了什么
  5. 点击绿色 Commit changes 按钮保存

常见编辑场景

场景操作Commit 示例
写开发日志新建文件 docs/dev-log-日期.mddocs: 添加 05-14 开发日志
写训练记录新建文件 docs/training-logs/train-001.mddocs: 添加训练记录 #001
更新代码编辑对应 .py 文件feat: 实现花朵检测
修 Bug编辑对应文件fix: 修复检测丢帧
💡
新建文件：在任意文件夹页面点击 Add file → Create new file，输入文件名（含路径如 docs/new-file.md）即可创建。
Command Line

使用 Git 命令行

适合需要提交多个文件、频繁修改的场景。

首次配置

# 克隆仓库到本地 git clone https://github.com/shiren23/citrus-yield-prediction.git cd citrus-yield-prediction

日常工作流

git pull
→
修改文件
→
git add
→
git commit
→
git push
# ① 每次开工前，拉取最新代码 git pull # ② 添加你修改/新增的文件 git add models/train.py docs/dev-log-2026-05-14.md # ③ 提交，写清楚做了什么 git commit -m "feat: 完成检测引擎封装" # ④ 推送到远程仓库 git push

只下载某个文件

# 下载单个文件（不克隆整个仓库） curl -O https://raw.githubusercontent.com/shiren23/citrus-yield-prediction/main/README.md # 下载指定文件夹下的文件 curl -O https://raw.githubusercontent.com/shiren23/citrus-yield-prediction/main/docs/dev-log.md
💡
URL 规则：https://raw.githubusercontent.com/用户名/仓库名/main/文件路径，替换路径即可下载任意文件。
Branch & Commit

分支与提交规范

分支命名

进行较大的功能开发时，建议创建分支而非直接改 main：

feat/功能名新功能开发如 feat/yolov8-detection fix/修复内容修复问题如 fix/detection-bug docs/文档内容文档更新如 docs/training-log exp/实验名实验性尝试如 exp/yolov8s-comparison
# 创建并切换到新分支 git checkout -b feat/yolov8-detection # 开发完成后推送 git push -u origin feat/yolov8-detection

提交信息格式

类型用途示例
feat新功能feat: 实现花朵检测功能
fix修复fix: 修复视频帧采样丢帧问题
docs文档docs: 添加模型训练说明
test测试test: 添加检测引擎单元测试
chore杂项chore: 更新依赖版本

合并代码（PR）

  1. 打开仓库页面 github.com/shiren23/citrus-yield-prediction
  2. 点击 Pull requests → New pull request
  3. 选择你的分支 → main
  4. 填写 PR 标题和描述（改了什么、为什么改）
  5. 通知团队成员 Review
  6. Review 通过后点击 Merge pull request

Record

记录规范

开发日志

在 docs/ 下按日期记录，文件名：dev-log-YYYY-MM-DD.md

模板
# 开发日志 2026-05-14 ## 今日完成 - 完成 XXX 功能开发 - 修复了 XXX 问题 ## 遇到的问题 - 问题描述及解决方案 ## 明日计划 - 待办事项

模型训练记录

在 docs/training-logs/ 下记录，文件名：train-NNN-描述.md

模板
# 训练记录 #001 - 日期：2026-05-14 - 模型：YOLOv8n - 数据集：xxx 张图片（train/val 划分） - 训练参数：50 epochs, batch=16, imgsz=640 - 结果：mAP@0.5 = 0.xx - 备注：xxx
📌
总结：三种方式选一种即可

网页上传/编辑 — 最简单，适合提交单个文件、写日志、改文档
Git 命令行 — 适合提交多个文件、频繁开发
下载文件 — 点击 Raw 按钮或用 curl 命令
⚠️
提交前先 git pull，避免冲突
不要提交大文件（> 25MB 用网盘分享链接）
不要提交敏感信息（密钥、密码、私有数据）
